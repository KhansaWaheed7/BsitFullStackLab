# BsitFullStackLab — EF Core + Blazor + Supabase

This project keeps the existing three-layer structure:

- **BlazorApp**: Blazor UI and application startup.
- **BusinessLogicLayer**: product validation and business operations.
- **DataAccessLayer**: EF Core `AppDbContext` and repository.
- **Model**: `ProductModel` used by the UI and data layer.

Product CRUD and search use **Entity Framework Core**. The repository does not use raw SQL for CRUD.

## 1. Configure the Supabase connection securely

In Visual Studio, right-click **BlazorApp** → **Manage User Secrets**. Keep the key name `DefaultConnection`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=YOUR_HOST;Port=5432;Database=postgres;Username=YOUR_USER;Password=YOUR_PASSWORD;SSL Mode=Require"
  }
}
```

Use the exact connection details supplied by Supabase. If you use the Supabase session pooler, use its supplied host, port, and username. Do not put the real connection string in `appsettings.json` or commit it to GitHub.

The Blazor project already has a `UserSecretsId` configured. You do not need to run `dotnet user-secrets init` again for this project.

## 2. Existing database table mapping

The current project code was already written for a Supabase table named `public."Products"` with these case-sensitive columns:

| Column | Expected PostgreSQL type |
|---|---|
| `Id` | `bigint` identity / generated ID |
| `Name` | `varchar` or `text` |
| `Price` | `bigint` (whole-number price) |
| `Category` | `varchar` or `text` |
| `Description` | nullable `varchar` / `text` |
| `IsActive` | `boolean` |

`AppDbContext` intentionally maps to this existing table and its column names to preserve your current database and data. Do not run the lowercase `public.products` schema from a different lab over this existing table unless your instructor specifically requires that different schema.

If you have not created the existing table, this SQL is a matching starting point (run it only if the table does not already exist):

```sql
create table if not exists public."Products" (
    "Id" bigint generated by default as identity primary key,
    "Name" varchar(200) not null,
    "Price" bigint not null check ("Price" >= 0),
    "Category" varchar(100) not null,
    "Description" varchar(500),
    "IsActive" boolean not null default true
);
```

## 3. Run the application

Open `BsitFullStackLab.slnx` in Visual Studio, set **BlazorApp** as the startup project, restore NuGet packages, and run it. Open the home page (`/`) for the existing product management UI.

If running from a terminal, from the `BlazorApp` folder:

```bash
dotnet restore
dotnet run
```

## 4. Test the lab

1. Open the home page and check that products load from Supabase.
2. Add a product with a name, non-negative whole-number price, category, description, and active status.
3. Edit the product and save the changes.
4. Search by name, category, or description.
5. Delete a product and confirm the prompt.
6. Refresh the page and restart the app; the saved changes should remain in Supabase.
7. Verify the same changes in the Supabase Table Editor.

## 5. What the technologies do

- **Blazor** builds the interactive web interface in C# and Razor.
- **EF Core** maps C# objects to database rows and performs CRUD operations.
- **Npgsql EF Core provider** lets EF Core communicate with PostgreSQL.
- **Supabase** hosts the PostgreSQL database used to store product data.

## Notes

- The connection-string key used by this project is `ConnectionStrings:DefaultConnection`.
- The database password must remain in User Secrets locally and in secret/environment-variable settings when deployed.
- The project targets .NET 10 and uses EF Core/Npgsql provider 10.x packages.
- Product prices are currently stored as whole-number `bigint` values because that is how the existing model/table was configured. If the database column is changed to `numeric(10,2)`, update `ProductModel.Price` to `decimal` and adjust the form/model mapping too.
